# Android WebView performance runner

Run from an already open app state with Node 22 or newer and ADB available: `node scripts/regression/run.mjs --serial DEVICE --config private/performance-scenarios.json`. No device is selected implicitly. The private JSON config contains `appVersion`, optional `attempts` (default 3), and `scenarios`. Each scenario has `id`, `budget`, `kind` (`image`, `video`, `audio`, or `element`), `clickSelector`, `resultSelector`, and for media an expected `sourceIncludes`; optionally add `requireSourceChange: true`. Optionally set `timeoutMs` and `minimumAdvanceSeconds`. Selectors must identify the actual app control and output. Use distinct starting states externally for repeated attempts; the runner does not reset navigation or caches. A missing target, incorrect state, or timeout is a failed or blocked attempt, never a pass.

The timing begins immediately before finding and clicking the control inside the WebView and ends when the DOM probe succeeds. Images require successful decode, nonzero dimensions, viewport intersection and an unobscured center point. Video requires two progressing video-frame callbacks and an unobscured visible element. Audio requires a stable selected source and advancing playback time; audible output is unverified. DOM visibility is not screenshot pixel verification and does not establish that a video frame is nonblack. Element probes establish visible DOM state only; they do not establish media output. Choose appropriate scenarios and prepare cold/warm states independently.

Reports default to `private/performance-report.json`. Use `--screenshots true` to save display screenshots under `private/performance-evidence` (or `--evidence-dir PATH`); they are evidence only and are not automatically inspected. Scenarios with `verifyPixels` sample the element's own source inside its painted `object-fit` box and require a match in both a CDP viewport capture (exact CSS-pixel mapping through `devicePixelRatio`) and the display capture. The display capture must be exactly the edge-to-edge WebView; insets, split screen, rotation or pinch zoom fail with a reason (`pixelReason`) instead of being guessed. Build identity hashes every build input (`app/`, `public/`, `patches/`, lockfile, configs) and every served file in `dist/client`. Configs, screenshots, reports and baselines may contain private data. Keep them in `private/`. Explicitly create a baseline with `--capture-baseline private/baseline.json`; an existing file is never overwritten. Compare with `--baseline private/baseline.json`. Device, app version, scenario ID, budget and measurement level must match. Each absolute failure is counted; relative limits apply to medians. Percentiles use nearest rank, except the median averages the two middle values. Missing or incompatible baseline results block comparison. Scenario IDs and output paths appear in private output; avoid secrets in IDs or paths.
